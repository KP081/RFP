You extract structured data from a tender / RFP document (consultancy, IT services, works, goods). The document is given above. Fill the JSON schema below from it.

GENERAL RULES
- Use ONLY what this document states. If a value is not stated, use null (or an empty list). Never guess.
- Never fill values from your knowledge of standard templates or "usual" defaults (for example a typical maximum number of JV members). Report a number only if this document states it. Where a Data Sheet or appendix amends a general clause, report the amended value; if the document says which clause prevails, follow it.
- Read the whole document, including tables, annexures, appendices, formats and scanned/image pages (read those from the page image). A table may continue on the next page without a header row: treat continuation rows as part of the same table and use the headers of its first page. Never stop a list or table early: read every numbered item to the end.
- SAMPLE AND FORMAT PAGES: report formats, sample tables and blank forms often contain placeholders or illustrative numbers (for example "<source>", "Xx km", sample costs in a "format of DPR report"). These are NOT facts about this tender: never take project facts (cost, length, dates, names) from them. A form that is filled with this tender's own figures (for example a summary of the estimated cost) may be used.
- If the document contradicts itself (for example sub-items add up to more than the stated maximum), copy the numbers as written. Do not correct or "fix" them.
- Do not add up or compute totals yourself. Fill a total (key_person_months_total, all_staff_person_months_total) only if the document itself prints that total; otherwise null.
- Amounts: INR numbers (1 lakh = 100000, 1 crore = 10000000). Keep the wording from the document in raw_text. If a figure is given both with and without taxes, put the figure INCLUDING taxes in value_inr, set includes_tax to true, and keep both figures in raw_text.
- Dates: ISO YYYY-MM-DD, without time. If a date cannot be converted, copy the text as written.
- Percentages: plain numbers (5 means 5%), not fractions.
- Enum fields: pick the closest allowed value; use "other" if nothing fits and put the document's own wording in the matching *_text field when one exists.
- Security status (bid security, performance security): "required", "nil" (the document gives the amount as NIL / none needed; use "nil" even if a bid-securing declaration is permitted instead), "declaration_allowed" (only a bid-securing declaration is asked for, with no amount stated as NIL), or "not_stated" (the document does not mention it). null and "nil" mean different things: do not confuse them.
- document_kind: "corrigendum" if the document is an addendum/corrigendum containing only changes; fill only the fields it changes. Otherwise "tender_document".
- project.packages: only if the document lists two or more packages/lots.

PERSONNEL AND EVALUATION
- key_personnel.roles: list the key experts first, then sub-professional/support staff only if they are listed with roles. Include EVERY expert the document marks as conditional or as a replacement (for example needed only if tunnels are proposed, or only in hilly terrain), with is_conditional = true, the condition text (include the stated duration, such as "4 months") and the rate from the same note.
- rate_inr_per_month and cost_inr come from the remuneration / cost estimate table (columns: position, rate, staff-months, amount). Read the columns carefully; if a figure cannot be matched to its role with certainty, use null.
- min_experience_years only if the document states a hard minimum that disqualifies a person. Marking bands such as "<15 years = 0 marks, 15-18 years = 11 marks" are scoring bands, NOT minimums: never copy them there.
- Marks given to a role in the technical score go in technical_weight_points; the maximum of the individual CV scale in individual_max_points; a minimum pass percentage in min_score_pct.
- Evaluation tree has three levels: criteria -> sub_criteria -> bands. Keep each band's text exactly as written ("> 10 to <= 20") and put its points separately. Give bands for every sub-criterion that has them. Do not compute scores yourself.
- Combined-score weights go in evaluation.weights: technical_pct for the technical score; financial_pct ONLY for a score based on the price/financial proposal; any other component (a DPR or other rating, a quoted performance guarantee / PBG quote, and similar) goes in evaluation.weights.other with its own name.

CONTRACT
- Delay: liquidated damages and a separate "penalty for delay" can be different clauses with different rates. Put the clause that applies to delay in completing the services in contract.liquidated_damages; put any other delay-related clause in additional_conditions with category "delay damages".

OTHER
- Conditions that matter to a bidder but fit no field (local office, security audit, MSME exemptions and similar) go in additional_conditions: at most 10, one short sentence each.
- Do not output any field that is not in the schema.
